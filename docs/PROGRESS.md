## Log

### Phase 4: language, theme and polish

- **Urdu and English:** typed string dictionary with a test that both languages have the same keys and placeholders (D15); Urdu prayer names, statuses, months and weekdays; reminder notifications follow the chosen language.
- **RTL:** right-to-left layout applied instantly through the `direction` style (D16).
- **Dark mode:** light and dark palettes plus a System / Light / Dark setting (D18); status bar, tab bar and screens follow it.
- **Accessibility:** every control has a role and label (the status is read with the prayer name), touch targets are at least 48 dp, live regions announce time changes, and the emoji tab icons are hidden from screen readers.
- **Branding:** new app icon, adaptive icon, splash and notification icon generated by `scripts/generate-icons.py` (D17); Android notification plugin configured.
- **Verified:** 72 Jest tests, type-check, lint, format, Android bundle builds.
- **Still to confirm on a phone:** Urdu RTL layout, dark mode, a TalkBack pass, and the new icon.
- **Next:** Phase 5 (release).

### Phase 3: streaks and stats

- **Logic (tested):** `stats.ts` (current and best streak, range totals and congregation percentage, daily counts) and calendar helpers in `dates.ts` (`monthGrid`, `addMonths`, `weekdayIndex`).
- **Streak rules:** a day counts with at least N congregation prayers (setting, default 5); an incomplete today does not break the streak (D13).
- **Screens:** Stats tab (current and best streak, 7-day bar chart, week and 30-day summaries); History is now a month calendar with colour by congregation count and a day editor for past days (D14); a shared `DayEditor` is used by Today and History.
- **Verified:** 67 Jest tests, type-check, lint, format.
- **Next:** Phase 4 (Urdu and RTL, dark mode, accessibility, icon).

### Phase 2: built

- **Data:** migration v2 (`prayer_times`), typed settings with validation and defaults (Karachi method, Hanafi Asr), cache repository keyed by location (D10).
- **Aladhan client:** parses `"05:39 (PKT)"` times and `DD-MM-YYYY` dates, rejects malformed months, maps failures to `city_not_found` / `network` / `bad_response`; `ensureTimes` caches whole months and falls back to older cache offline.
- **Reminders:** pure `planReminders` (rolling 7 days, offset, stable ids), thin Expo wrapper with an Android channel and permission request, rebuilt on app open, foreground, settings change and day change (D12).
- **Screens:** Settings tab (city, country, method, Asr school, reminders with offset, live preview of today's times); Today shows each prayer's time and a note when times are saved or unavailable.
- **Verified:** 51 Jest tests, type-check, lint, format, and the Android bundle builds.
- **Device checks still to do on a phone:** a reminder firing in Expo Go, offline Today, changing school moves Asr. Background reliability is a Phase 5 check.

### Phase 2: design

- Read the SDK 58 notifications docs and called the live Aladhan API. Findings that shaped the design: monthly calendar endpoint, `"05:39 (PKT)"` time format, HTTP 400 for unknown cities, and a **44-minute Asr difference between schools** (Karachi, 27 Nov 2026: 15:22 vs 16:06), so `school` is a visible setting.
- Local notifications work in Expo Go on Android; background reliability must be confirmed in Phase 5 with an installable build.
- Wrote [phases/phase-2.md](phases/phase-2.md) with the data model, the parts to build, task list and test plan.
- **Next:** review the design, then build tasks 1 to 4 (cache, API client, reminder planning) with tests.

### Phase 1: Core check-in

- **Logic (tested):** `dates.ts` (local day keys, DST-safe `addDays`, midnight timer), `status.ts` (tap cycle, day summary).
- **Storage:** `expo-sqlite` with a versioned migration (`PRAGMA user_version`) and a repository (`setStatus`, `getDay`, `getRange`). SQL is tested against a real in-memory SQLite (decision D8).
- **Screens:** Today (tap to cycle, long-press to clear, summary line) and History (last 14 days with five status dots) in a tab layout. Today rolls over at local midnight and when the app returns to the foreground. An error boundary shows database failures instead of a blank screen.
- **Verified:** 23 Jest tests (date tests also run in four time zones), type-check, lint, format, and the Android bundle builds.
- **Still to confirm on the phone:** marks survive closing the app; rollover at midnight (change the phone date); airplane mode.
- **Next:** Phase 2 (prayer times and reminders).

### Phase 0: Foundation

- Scaffolded Expo SDK 58 with Expo Router and TypeScript (strict). Renamed to Jamaat Tracker (`com.saadalikhan.jamaattracker`), removed the template demo screens.
- Added Jest (`jest-expo`), ESLint (`eslint-config-expo`), Prettier, `.nvmrc` (Node 22) and a GitHub Actions workflow that runs format, lint, type-check and tests.
- Created the first domain module (`src/domain/prayers.ts`) with a test, and a placeholder home screen that imports it through the `@/` alias.
- **Verified locally:** format, lint, type-check, 2 tests and `expo-doctor` (20/20) all pass on Node 22.
- **Found:** the Expo lint tooling needs Node 22.13 or newer, so Node 20 is not enough. The plan and CI now use Node 22.
- **Still to confirm:** the app opening on a real phone through Expo Go (needs the author's device).
- **Next:** Phase 1 (core check-in with SQLite). The detailed design and task list are in [phases/phase-1.md](phases/phase-1.md).
